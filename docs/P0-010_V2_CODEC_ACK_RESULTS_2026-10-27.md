## 真正跑过的测试

[GitHub Actions #40471145109](https://github.com/wpuu/kof/actions/runs/40471145109)：
**18 tests / 18 pass / 0 fail**。

覆盖如下：
- V2 全部消息类型编解码及多种异常包被拒绝；
- 身份/比赛ID/配置版本不匹配拒绝；
- 严格输入 frame 边界、mask 范围、ACK 位图、单帧/五帧输入缺失请求与历史重发；
- 过期关键输入无法恢复时故障终止，不允许继续假装成绩可信；
- 伪造未来累计ACK或选择确认不得清除真实输入历史；
- 有界历史缓存与重传次数；
- 虚拟60Hz条件下“单向额外90ms相当于约6帧等待＋4连丢”安全中止，而不是继续安静分叉。

从静态源码到可复核CI，这一阶段不再是纸面方案。

## 必须如实保留的限制

1. **尚未集成实际双人浏览器游戏**；因此不可以声称刚编写的 V2 已使 Neon Fist 90ms＋4连丢恢复为一致。
2. 单元测试的“五帧补回”在模拟时间不推进或仍在允许窗口内成立；真实延迟会导致超过可回滚的窗口，届时必须暂停、重同步或作废。**不允许把二者混为一谈**。
3. 这是实验性连接内核，尚未验证身份会话、消息重放抵抗、ACK数据包流控、完整恶意数据审计、网络性能与崩溃保护。
4. 控制通道与快速输入通道的实际 WebRTC 适配器、比赛时间轴和确定性状态存取仍需施工；不能接有价值的天数赔率自动结算。
5. 未取得版权授权前，不得提供 KOF ROM 等受保护游戏内容；合法内容/付费运营资质分别审核。
