## 测试分为三层，不得混淆

### L0：源码与许可证检查
- 只拉取代码与必要的原始测试资源，不拉取非商用第三方素材。
- 检查 README、LICENSE、所有 ASSET 许可证；记录 commit SHA 和依赖锁定版本。
- 记录 npm 真实脚本：Neon Fist 的 package.json 只有 `test`、`server`、`dev`，无 `start`。
- 不在公网部署含未授权 `/api/admin/*` 的服务。先本地运行 `npm test`、启动静态客户端，留退出码和简短结果。
- **本轮尚未运行上述命令；没有判定测试通过。**

### L1：网络链路单独验证
使用 `lab/p2p_probe.html`（静态页面、WebRTC DataChannel，默认 STUN，无 TURN）测能否 P2P 建立连接、连通等待时间、应用层 RTT、超时和 candidate 类型。它不能测游戏帧同步或真正的游戏输入延迟。

最少应测组合：
1. Windows Chrome ↔ Windows Chrome，同路由器。
2. Windows ↔ 华为 Android Chrome，同一 Wi-Fi。
3. Windows 家宽 ↔ iPhone Safari，跨运营商／手机移动数据。
4. 华为 Android ↔ iPhone Safari，分属不同互联网连接。
5. 至少增加一组运营商不同地区的远端用户；有条件再试网络切换。

每组至少 10 次独立连接尝试，每次有效连接运行 2 分钟。记录连接成功数、建立时长、候选对类型、RTT p50 / p95、应用层超时、失败原因；失败不能静默排除。**STUN 不等于 TURN，直连失败需要另设计中继。**手动交换 SDP 时请勿公开粘贴在社交网络，因为可能携带连接元信息。

通过门槛（*拟定工程目标，不是实测事实*）：
- 同 Wi-Fi 组合：至少 9/10 次建立有效通道。
- 异网组合：至少 8/10 次直连；低于目标则先补 TURN/备用连通方案并复测，不直接判断整个产品失败。
- 页面测试工具可显示当前连接状态、往返延迟与超时，不把浏览器 RAF 帧率当格斗游戏 FPS。

### L2：Neon Fist 游戏本体端到端验证
按 `README` 与真实 package.json 启动，仅在隔离/本地测试环境。测试 Windows 与手机横屏、手柄/触控、60 FPS 目标、回滚时操作是否自然。

最低验证目标（均未完成）：
- Windows + 安卓 + iOS 各完成 ≥ 20 个完整的对局；
- 逐场记录是否崩溃、不同步、黑屏、断线、角色手感、按钮误触；
- 角色移动、轻重输入、搓招、取消、防御、两端判胜一致性均可操作；
- 记录实测游戏 FPS、帧时长 p95、Rollback 次数和滞后帧数、game-state checksum，而非只看网络 RTT；
- 实测 30/60/100/150 ms RTT 以及抖动/丢包人工环境，记录玩家是否能完成连续 20 局；
- 如果 P2P 无法直连，明确标记未测试，不得说“0 延迟”。

### L3：上线前安全与经济门禁
必须先完成账户身份验证、玩家身份与结果提交校验、服务端审计、管理权限、真实数据库及备份、支付隔离、用户数据保护；来源代码只作候选。

任何买来可以兑换付费服务的天数用于比赛/观众输赢的方案，必须先有适用司法辖区的法律意见及支付提供商批准，未经确认不开展真钱/有价权益测试。
